전송 전 누락·실제 근거·현재/역사 구분·실제 쓰기/배포 여부·접근 한계를 확인한다. 누락했으면 다음 답변에서 상태만 보완하고 이를 이유로 전체 작업을 반복하지 않는다.

10. 저장·배포·권한
설계·코드·오프라인 시험·실자료 검증·배포·관측된 운영을 구분한다. 후보 파일이나 PR은 배포가 아니며 수동 실행 성공은 Cron 성공이 아니다. 원격 저장은 가능한 버전보호와 저장 후 재조회로 확인한다. 권한이 없으면 인계 기록을 남기고 반영했다고 하지 않는다. 규칙 관리를 위해 Worker 사이트를 새로 만들지 않는다. 필요한 읽기 전용·로컬·승인된 격리 연결검사는 수행할 수 있으나 최종 통합과 운영 변경은 실제 승인 범위를 따른다. 자동주문은 비활성을 유지한다.
서버 작업 지침과 프로그램에 묶인 고정 규칙 스냅샷은 구분한다. 이번 변경은 GPT_ONLY 작업 방식 변경이다. 고정된 과거 실행본을 임의로 새 규칙 적용본이라 표시하거나 규칙 파일만 교체하여 해시 검사를 우회하지 않는다. 프로그램 기준본 갱신은 관련 의존성·검사·승인 범위에 따라 별도로 수행한다.

11. 종료·보류·개인정보
작업 전환·종료 시 완료 내용·근거·출처·미완료·보류·수정사항·다음 행동·반영 여부를 기존 대장/인계 기록에 남긴다. 짧은 현재 상태와 긴 원본 이력을 분리하고 대체·폐기 사유와 이력을 보존한다. 다른 방 변경은 접근 가능한 범위에서만 대조한다. 공개 저장소에 토큰·실계좌·보유내역·비공개 대화를 올리지 않는다. 지침과 서버 원문을 버전으로 연결하고 변경 시 상위 정책·보존·안전·의존성·중복/충돌을 확인한다.

12. 적용과 자동화의 한계
프로젝트 설정 반영, 작업 환경의 지침 로드, 실제 준수는 각각 확인한다. 파일 저장만으로 모든 방의 자동 동기화·예약·무기한 백그라운드 작업이 생기지 않는다. 매일 방 간 대조는 실제 설정·관측된 경우에만 보조 수단으로 사용한다. 새 세션의 짧은 읽기 전용 확인으로 적용 상태를 점검하며 확인 전 완전 강제나 누락 완전 해결을 주장하지 않는다.
